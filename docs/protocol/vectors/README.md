# Golden vectors

`device.vectors` holds wire bytes, positive and negative, that the Python codec (`tinyaisense-wire`) and the C codec (firmware) must both pass. `agent.vectors` holds the agent API's [binary frames](../agent.md#binary-frames), which only the Python codec speaks. Both files are generated by `generate.py`: edit the generator, then run

```sh
uv run python docs/protocol/vectors/generate.py
```

A wire test fails when the committed file and the generator's output differ.

## File format

Plain ASCII text, one statement per line, no line longer than 120 bytes. Lines starting with `#` are comments, and blank lines are ignored. Each vector is a block:

```
vector tcp/ping
layer tcp
expect ok
# frame type=1 flags=0 len=29
# {"type":"ping","t":123456789}
hex 01 00 1d 00 7b 22 74 79 70 65 22 3a 22 70 69 6e
hex 67 22 2c 22 74 22 3a 31 32 33 34 35 36 37 38 39
hex 7d
end
```

| Statement | Meaning |
|---|---|
| `vector <name>` | starts a block. Names are unique |
| `layer <layer>` | which decoder the bytes go to: `tcp` or `udp` in `device.vectors`, `agent_to_hub` or `hub_to_agent` in `agent.vectors` |
| `param <key> <integer>` | optional, repeatable: context the decoder needs |
| `expect <outcome>` | `ok`, `ignore`, or a decode error code |
| `hex <bytes>` | the input, as space-separated hex byte pairs. Repeated lines concatenate |
| `canon <bytes>` | optional: the expected re-encoding, when it differs from the input. Repeated lines concatenate |
| `end` | ends the block |

## Layers

**`tcp`**: the bytes are a TCP byte stream holding whole frames. Feed them all to the control decoder, then signal the end of the stream.
- JSON frames (type 1) decode to messages. Frames of other types and messages of unknown `type` are skipped.
- Re-encoding means encoding every decoded message, in order, as a type-1 frame with `flags` 0, and concatenating the frames.

**`udp`**: the bytes are one datagram.
- A stream frame (kind 1) is re-encoded as is. When the vector has the params `rate`, `channels`, `frame_ms` and `final`, the payload is also checked against the frame rules for a `pcm_s16le` stream of that format; `final 1` means it's the stream's final frame.
- An event mirror (kind 2) decodes its payload as an `event` message, and is re-encoded from that event.

**`agent_to_hub`** and **`hub_to_agent`**: the bytes are one binary WebSocket message of the agent API, in that direction. It decodes to its header fields and its PCM, and re-encodes as is.

## Outcomes

| `expect` | The codec must |
|---|---|
| `ok` | decode without error, and re-encode to the `canon` bytes if given, else to the input bytes. `canon` bytes are canonical themselves: they round-trip unchanged |
| `ignore` | decode without error and yield nothing to act on: only skipped frames or messages (`tcp`), or an unknown datagram kind (`udp`) |
| an error code | fail with exactly that code. The codes are listed under [Decode errors](../device.md#decode-errors) and, for binary frames, under [Binary frames](../agent.md#binary-frames) |

A `tcp` vector's frames decode in order, and the first error wins. Within one frame or datagram, a negative vector breaks exactly one rule, so the order in which a codec runs its checks doesn't change the outcome.
